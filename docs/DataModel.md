# Data Model

This document describes the content entities the app consumes today, and how they get from data to screen. See `docs/GoogleSheets.md` for where the data originates.

## Overview

All content is static JSON, bundled into the app at build time — there is no runtime API or database. Each entity has:
1. A TypeScript type in `src/data/types.ts`.
2. A JSON file in `src/data/` with the actual content.
3. A thin service in `src/services/` that imports the JSON and exposes a getter — this is the only place components should import content from.

## Entities (`src/data/types.ts`)

### `Place`
The core entity, backing the Map, Explore, and My Rome tabs. Fields include:
- Identity/display: `id`, `name`, `category` (one of the 7 keys in `src/config/categories.config.ts`), `lat`, `lng`, `imageUrl`.
- Common metadata: `visitDuration`, `bookingUrl`, `openingHours`, `entranceFee`, `officialSite`.
- **Editorial fields** (populated mainly for the `gallery` category, but not exclusive to it): `whyWeLoveIt`, `insiderTip`, `localSecret`, `didYouKnow`, `nearbyRecommendations`.

A place's category still carries a **tier** via `CATEGORY_META[category].tier` (`'premium'` for `gallery`, `'utility'` for everything else), but as of the Phase 4 redesign this no longer selects a different rendering component — `PlaceScreen.tsx` (`src/features/map/PlaceScreen.tsx`) is the single template for every place, and each editorial section simply doesn't render when its field is missing on the data. `tier` is otherwise unused in `src/` today.

### `Experience`
Video-based highlighted experiences shown on the Experiences tab, each tied to a specific guide.

### `Testimonial`
Customer reviews shown on My Rome.

### `Guide`
Guide bios (photo, name, bio, WhatsApp contact) shown on My Rome.

### `Collection`
Defined in `types.ts` but **not used anywhere**: no JSON data file, no service, no UI consumer. It models a themed grouping of places (e.g. for a future "Collections" browsing mode) but was never wired up. Do not build against it without first confirming it's still meant to be built out — see `ROADMAP.md`.

### `AppContent`
Home-screen editorial content, keyed by `AppContentSection`: `'hero' | 'tip_of_the_day' | 'get_around' | 'emergency' | 'discount'`.

## Services (`src/services/`)

One file per entity (`placesService.ts`, `experiencesService.ts`, `testimonialsService.ts`, `guidesService.ts`, `appContentService.ts`), each following the same ~10-line pattern: import the JSON, expose a `getX()` function. `collectionsService.ts` also exists but has zero call sites — it exports `getCollections()` for the unused `Collection` entity above.

`placesService.ts` carries a comment noting the JSON it wraps is generated by an external `export_places.py` script from a Google Sheet — see `docs/GoogleSheets.md`.

## How the store consumes this

`src/store/usePlacesStore.ts` calls `placesService.getPlaces()` once, on `loadPlaces()`, and holds the result in its own `places` array (plus `selectedPlace`, category/radius filters, and saved-place ids). Screens read places through the store, not through the service directly, except where a screen only needs a one-off read (e.g. Experiences/My Rome pulling guides/testimonials directly from their services since those aren't part of the shared store state).
